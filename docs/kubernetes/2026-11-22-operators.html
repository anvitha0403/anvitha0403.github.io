Kubernetes Operators

Kubernetes Last Updated: 2026-11-22 Learning

One-Line Summary

An Operator extends Kubernetes by introducing custom resources and a controller that automates operational tasks.

Why Does It Exist?

Kubernetes knows how to manage Pods, Deployments, StatefulSets, Services, and other built-in resources.

It does not know how to manage a PostgreSQL cluster, Kafka cluster, Redis cluster, or any domain-specific system.

Operators teach Kubernetes how to manage these systems.

Problem It Solves

Without operators:

  • Manual backups
  • Manual failover
  • Manual scaling
  • Manual upgrades

Operators automate these operational tasks.

Core Concepts

CRD (Custom Resource Definition)

Introduces a new Kubernetes resource type. 


kubectl get postgresql

The "postgresql" resource exists because a CRD was installed.

Custom Resource (CR)

Actual instances of a CRD. 


apiVersion: db.example.com/v1
kind: PostgreSQL
metadata:
  name: primary
spec:
  replicas: 3

Controller

Watches resources and continuously compares desired state to actual state.

Mental Model

A Deployment Controller manages Pods.

An Operator is just another Controller that manages a higher-level concept such as PostgreSQL, Kafka, Elasticsearch, or MongoDB.

Deployment → Pod
PostgreSQL Operator → PostgreSQL Cluster

Architecture / Flow


Custom Resource Created
            ↓
      Operator Watches
            ↓
      Reconcile Loop
            ↓
 Desired State != Actual State
            ↓
     Make Necessary Changes
            ↓
      States Match

Interview Answer (30 Seconds)

This is the answer I'd give in an interview.

A Kubernetes Operator extends Kubernetes using Custom Resource Definitions (CRDs) and controllers. The CRD introduces a new resource type while the Operator watches those resources and continuously reconciles actual cluster state with desired state. Operators are commonly used to automate management of complex stateful systems such as PostgreSQL, Kafka, MongoDB, and Elasticsearch.

Interview Questions

What is a Kubernetes Operator?

A controller that watches custom resources and performs domain-specific automation.

What is the difference between a CRD and an Operator?

A CRD defines a new Kubernetes resource type. An Operator contains the logic that manages instances of that resource.

Can a CRD exist without an Operator?

Yes. Kubernetes can store the resource, but nothing will react to it.

How is an Operator different from a Deployment?

A Deployment manages stateless workloads. Operators typically manage complex stateful systems and automation workflows.

What is the reconciliation loop?

The reconciliation loop continuously compares desired state and actual state and takes actions until they match.

Tradeoffs

Pros Cons
Automates repetitive operations Extra complexity
Encapsulates operational knowledge Learning curve
Improves reliability Harder debugging

Common Mistakes

  • Thinking CRD and Operator are the same thing.
  • Assuming Operators execute only once.
  • Ignoring the reconciliation loop.
  • Treating Operators as scripts instead of controllers.

Blog Learnings

  • Operator = CRD + Controller Logic.
  • Everything revolves around reconciliation.
  • Most Operators manage stateful workloads.

Personal Understanding

Operator = Deployment Controller, but for my own resource type.

Kubernetes ships with generic controllers. Operators allow developers to write custom controllers for domain-specific systems.
